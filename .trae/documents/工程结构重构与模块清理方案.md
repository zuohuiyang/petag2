- 将 `pctag.vcxproj` 与 `unittest.vcxproj` 统一迁移到 `build\msvc\` 目录：
  - 路径示例：`build\msvc\pctag.vcxproj`、`build\msvc\unittest.vcxproj`

  - `pctag.vcxproj:44-52` 与 `unittest.vcxproj:35-43` 的 `OutDir`/`IntDir` 已使用相对根路径 `..\out\...`，在 `build\msvc\` 下保持一致，无需修改。

## 与原方案的衔接
- `.sln` 迁移：根目录下新 `.sln` 文件指向 `build\msvc\` 两个项目文件，其他内容不变。
- 模块保留/移除与 CLI 调整：保持原方案全部细节（保留 `read`/`insert`/`help`，移除 `verify`/`diagnose`/`dump`）。
- 输出重命名：
  - `tools/pctag.vcxproj` 改为 `build/msvc/pctag.vcxproj` 后仍将 `<TargetName>` 统一改为 `petag2`（Debug/Release、x64 与新增的 Win32）。
  - 脚本与文档统一更新为 `petag2.exe`。
- x86/x64 构建：在 `build\msvc\` 下扩展 Win32 平台配置并在 `.sln` 中映射即可。

## 迁移步骤（精简）
1. 创建 `build\msvc\` 目录，将 `tools\pctag.vcxproj`、`tools\unittest.vcxproj` 与关联的 `*.filters`（若有）移动过去。
2. 在根目录添加新的 `.sln`，将项目引用改为 `build\\msvc\\pctag.vcxproj`、`build\\msvc\\unittest.vcxproj`。
3. 按原方案执行模块清理、CLI 与帮助更新、输出名重命名、Win32 平台扩展与第三方库多架构支持。
4. 执行清理与 Rebuild，跑测试与脚本，收集日志与二进制校验信息。

## 说明
- 相比将项目文件放在 `tools/`，`build/msvc` 更符合多工具链的组织习惯；未来若加入 CMake 或 Ninja，可对应增加 `build/cmake`、`build/ninja` 等目录，不影响源码布局。
